### 1) Helper export gap (`multisig/tooling/federated-v1-actionhash.ts`)

Required by brief for Deliverable 1:
- import `padToBytes32`/`uintToBytes32` from `multisig/tooling/federated-v1-actionhash.ts`
- do not reimplement

Observed:
- `computeDirectApprovalMessage` and `computeFederatedApprovalMessage` are exported
- `padToBytes32` and `uintToBytes32` are declared as local functions (not exported)

Consequence:
- Cannot satisfy "import, do not reimplement" without modifying `multisig/tooling/` (explicitly read-only for this WI).

### 2) Seat-seed format ambiguity

Required by brief for Deliverable 2:
- `--seat-seeds <path>` JSON format matching `deploy-tariff-registry-preview.ts`

Observed in `deploy-tariff-registry-preview.ts`:
- seat derivation is internal via `buildPilotSeats()` with deterministic seeds
- no external JSON file schema for seat seeds is defined

Consequence:
- Any `--seat-seeds` JSON schema here would be design-guessing, which the brief disallows.

### 3) Witness plumbing surface not evident on `deployed.callTx`

Required by brief for Deliverable 4:
- pass witness provider through `deployed.callTx[circuitName]`

Observed in `@midnight-ntwrk/midnight-js-contracts@4.0.2` types:
- `callTx` overloads are:
  - `(...args) => Promise<FinalizedCallTxData>`
  - `(txCtx, ...args) => Promise<CallResult>`
- no `witnesses` argument appears in these signatures

Consequence:
- No explicit call-site witness-injection contract discovered from the SDK type surface in this worktree.
