## 2. Source-level specification

### 2.1 `LaneRecord` struct (declared alongside `ScheduleRecord`)

Field order below is canonical for the record's byte layout and for
every hash that folds a `LaneRecord` in — Cursor MUST NOT reorder.

```
struct LaneRecord {
  scheduleId:        Bytes<32>,
  laneKindByte:      Uint<8>,
  leviedBy:          Bytes<32>,
  bpsShare:          Uint<16>,
  remitAddress:      Bytes<32>,
  basis:             Uint<8>,
  applicabilityHash: Bytes<32>,
  statuteRefHash:    Bytes<32>,
  effectiveEpoch:    Uint<64>,
  retiredEpoch:      Uint<64>,       // 0 = live
  remittanceMode:    Uint<8>,        // CAL-11
  registeredAt:      Uint<64>,
}
```

Field notes:

- `scheduleId` — the parent schedule's id. MUST resolve to a live
  entry in `_registeredSchedules` at register-lane time
  (`SCHEDULE_NOT_FOUND` / `SCHEDULE_NOT_LIVE`). Set from the caller's
  `scheduleId` param, `disclose()`-wrapped.
- `laneKindByte` — enum 0=VAT, 1=levy, 2=cess, 3=duty per
  STATUTORY-LANES-MODEL §2. Circuit does not enforce a max byte value;
  interpretation is off-chain (WI-17 renderer).
- `leviedBy` — canonical authority id ("KRA", "EPRA", county-id, ...).
  Circuit treats it as opaque `Bytes<32>`. STATUTORY-LANES-MODEL B-4
  scope-to-nationRef is enforced off-chain by the statute-to-lane
  ceremony (STATUTORY-LANES-MODEL §7 R-3), not in-circuit.
- `bpsShare` — statute-set. NOT enforced-consistent with
  `SplitShares.statutoryTotalBps` in-circuit: an operator's aggregate
  is the ceiling that WI-13's `retuneClass` step 7 already checks;
  per-lane consistency with that aggregate is off-chain policy per
  STATUTORY-LANES-MODEL §7 change-ceremony rules. WI-13.1 stores the
  bps, WI-14 reads it, statutory correctness lives in the ceremony.
- `remitAddress` — where WI-14's settle circuit routes this lane's
  share. Opaque `Bytes<32>`; either a fiat-door marker or an on-chain
  address per `remittanceMode`.
- `basis` — enum matching STATUTORY-LANES-MODEL §2
  (0=pre-tax energy charge, 1=full retail price, ...). Opaque byte
  in-circuit.
- `applicabilityHash` — commitment to the off-chain per-class
  applicability rule (FULL / REDUCED / EXEMPT per class). Circuit
  stores the hash; rule text and per-class disposition live off-chain
  (STATUTORY-LANES-MODEL §5).
- `statuteRefHash` — commitment to the enabling-law citation. The
  R-3 change-ceremony publishes the full citation; the hash pins it
  on-chain.
- `effectiveEpoch` — MUST be strictly greater than
  `_currentEpoch.read()` at register-lane time (I-13.1-D via checked
  cast). Never retroactive.
- `retiredEpoch` — 0 while active; set to `_currentEpoch.read()` at
  retire-lane time. Retirement is one-way per record; a retired lane's
  key MAY be re-registered with a fresh record superseding
  (I-13.1-E).
- `remittanceMode` — CAL-11: 0=fiat-door, 1=on-chain per
  STATUTORY-LANES-MODEL §3. Circuit accepts any `Uint<8>` value;
  interpretation lives in WI-14's settle branch.
- `registeredAt` — block time from the `currentTime` argument
  (`blockTimeGte(currentTime)`-validated as in every V1 branch op).

### 2.2 New ledger declaration

Placed immediately after `_activeScheduleByNode` in the ledger section
(mirrors the schedule-map placement pattern from V1's `_registeredSchedules`
/ `_activeScheduleByNode` block):

```
// nodeId → active scheduleId (unchanged, existing).
// scheduleId + classPathHash → current ClassEntry (unchanged, existing).
// _registeredLanes: (scheduleId, laneKindByte) composite key → LaneRecord.
// Keeper-observable via _actionLog kind ∈ {1 LANE_REGISTERED,
// 7 LANE_RETIRED}. WI-14's settle circuit calls resolveLanes to route
// statutory shares in-circuit.
export ledger _registeredLanes: Map<Bytes<32>, LaneRecord>;
```

No new counters. No new sets. No new sealed constants.

### 2.3 `laneKey` helper

Placed alongside V1's composite-key helpers (the same section as
`classSplitKey`, if present, or after the `retuneNonce`-derivation
helper). Domain tag `pp:tariff:v1:laneKey` reserved here.

```
// Composite key for a statutory lane record (scheduleId + laneKindByte).
circuit laneKey(scheduleId: Bytes<32>, laneKindByte: Uint<8>): Bytes<32> {
  const kindBytes = (disclose(laneKindByte) as Field) as Bytes<32>;
  return persistentHash<Vector<3, Bytes<32>>>([
    pad(32, "pp:tariff:v1:laneKey"),
    disclose(scheduleId),
    kindBytes,
  ]);
}
```

Determinism: two callers passing the same `(scheduleId, laneKindByte)`
must produce byte-identical keys. `Uint<8>` → `Field` → `Bytes<32>`
mirrors V1's `effectiveEpochBytes = (disclose(effectiveEpoch) as Field)
as Bytes<32>` pattern.

### 2.4 `registerLane` circuit

Skeleton follows V1's `registerSchedule` exactly:
`assertInitialized` → `blockTimeGte` → schedule exists + live →
charter proof → action-hash construction → `consumeFederationApproval`
→ duplicate check → epoch check → insert → `emitAction`.

**Full parameter list (verbatim):**

```
export circuit registerLane(
  scheduleId:        Bytes<32>,
  laneKindByte:      Uint<8>,
  leviedBy:          Bytes<32>,
  bpsShare:          Uint<16>,
  remitAddress:      Bytes<32>,
  basis:             Uint<8>,
  applicabilityHash: Bytes<32>,
  statuteRefHash:    Bytes<32>,
  effectiveEpoch:    Uint<64>,
  remittanceMode:    Uint<8>,
  charterProof:      CharterProof,
  currentTime:       Uint<64>,
): []
```

**No operator signature parameter.** The lane is federation-gated
only — the federation IS the authority that translated the statute
into a `rateBps` via the R-3 change ceremony (STATUTORY-LANES-MODEL
§7). No operator key path.

**Action-hash payload composition** (this is the critical detail
Cursor must get exactly right — it determines off-chain
bundle-builder compatibility for the msfed 3-of-5 seat approval
signing). Vector length 14, field order:

```
persistentHash<Vector<14, Bytes<32>>>([
  pad(32, "pp:tariff:v1:registerLane"),   // domain
  selfBytes(),                             // contract self-binding (M-2)
  disclose(scheduleId),
  kindBytes,                               // laneKindByte as Field as Bytes<32>
  disclose(leviedBy),
  bpsShareBytes,                           // bpsShare as Field as Bytes<32>
  disclose(remitAddress),
  basisBytes,                              // basis as Field as Bytes<32>
  disclose(applicabilityHash),
  disclose(statuteRefHash),
  effectiveEpochBytes,                     // effectiveEpoch as Field as Bytes<32>
  remittanceModeBytes,                     // remittanceMode as Field as Bytes<32>
  currentEpochBytes,                       // _currentEpoch.read() as Field as Bytes<32>
  timeBytes,                               // currentTime as Field as Bytes<32>
])
```

**Error labels** (all REVERTs, per V1-DESIGN.md §8 "MUST fail means
REVERT, not warning event"):

- `SCHEDULE_NOT_FOUND` — schedule id not in `_registeredSchedules`.
- `SCHEDULE_NOT_LIVE` — schedule exists but `retiredEpoch != 0`.
- `SCHEDULE_UNCHARTERED_NODE` — from `assertCharterMembership` on the
  schedule's `rec.nodeId` (mirrors V1's registerSchedule step 3).
- `FEDERATION_APPROVAL_INVALID` — from `consumeFederationApproval`.
- `FEDERATION_APPROVAL_REPLAYED` — from `consumeFederationApproval`.
- `LANE_EPOCH_RETROACTIVE` — checked cast on `effectiveEpoch > currentEpoch`.
- `LANE_ALREADY_REGISTERED` — duplicate check per I-13.1-E.

**Full-body sketch** (top-to-bottom, mirrors registerSchedule L459+
byte-for-byte in shape):

```
export circuit registerLane(
  scheduleId:        Bytes<32>,
  laneKindByte:      Uint<8>,
  leviedBy:          Bytes<32>,
  bpsShare:          Uint<16>,
  remitAddress:      Bytes<32>,
  basis:             Uint<8>,
  applicabilityHash: Bytes<32>,
  statuteRefHash:    Bytes<32>,
  effectiveEpoch:    Uint<64>,
  remittanceMode:    Uint<8>,
  charterProof:      CharterProof,
  currentTime:       Uint<64>,
): [] {
  assertInitialized();
  assert(disclose(blockTimeGte(disclose(currentTime))),
         "registerLane: timestamp cannot be in the future");

  // (a) Schedule must exist and be live.
  const dSchedId = disclose(scheduleId);
  assert(_registeredSchedules.member(dSchedId), "SCHEDULE_NOT_FOUND");
  const schedRec = _registeredSchedules.lookup(dSchedId);
  assert(schedRec.retiredEpoch == 0 as Uint<64>, "SCHEDULE_NOT_LIVE");

  // (b) Charter proof binds the lane to the SCHEDULE'S nodeId.
  //     Same shape as registerSchedule step 3.
  assertCharterMembership(schedRec.nodeId, charterProof);

  // (c) I-13.1-D: effective epoch strictly in the future.
  //     Checked-cast underflow reverts if effectiveEpoch <= currentEpoch.
  const _epochGap = ((disclose(effectiveEpoch)
                      - _currentEpoch.read()
                      - 1) as Uint<64>);
  // If the above underflows, the whole circuit reverts with the compiler's
  // range-check message; Cursor MAY wrap with a labeled assert if the
  // compiler admits it, but the checked cast IS the assertion (V1 §5.4
  // idiom).

  // (d) Prepare the 14 hash inputs.
  const kindBytes         = (disclose(laneKindByte) as Field) as Bytes<32>;
  const bpsShareBytes     = (disclose(bpsShare) as Field) as Bytes<32>;
  const basisBytes        = (disclose(basis) as Field) as Bytes<32>;
  const effectiveEpochBytes = (disclose(effectiveEpoch) as Field) as Bytes<32>;
  const remittanceModeBytes = (disclose(remittanceMode) as Field) as Bytes<32>;
  const currentEpochBytes = (_currentEpoch.read() as Field) as Bytes<32>;
  const timeBytes         = (disclose(currentTime) as Field) as Bytes<32>;

  const actionHash = persistentHash<Vector<14, Bytes<32>>>([
    pad(32, "pp:tariff:v1:registerLane"),
    selfBytes(),
    dSchedId,
    kindBytes,
    disclose(leviedBy),
    bpsShareBytes,
    disclose(remitAddress),
    basisBytes,
    disclose(applicabilityHash),
    disclose(statuteRefHash),
    effectiveEpochBytes,
    remittanceModeBytes,
    currentEpochBytes,
    timeBytes,
  ]);

  // (e) I-13.1-A: federation approval + replay guard.
  consumeFederationApproval(
    actionHash,
    pad(32, "pp:tariff:v1:registerLane"),
  );

  // (f) I-13.1-E: duplicate check. Allow re-registration only if the
  //     existing key's record is retired (retiredEpoch != 0).
  const key = laneKey(scheduleId, laneKindByte);
  const dKey = disclose(key);
  assert(
    !_registeredLanes.member(dKey)
      || _registeredLanes.lookup(dKey).retiredEpoch != 0 as Uint<64>,
    "LANE_ALREADY_REGISTERED"
  );

  // (g) Insert the LaneRecord (retiredEpoch = 0 = live).
  const record = LaneRecord {
    scheduleId:        dSchedId,
    laneKindByte:      disclose(laneKindByte),
    leviedBy:          disclose(leviedBy),
    bpsShare:          disclose(bpsShare),
    remitAddress:      disclose(remitAddress),
    basis:             disclose(basis),
    applicabilityHash: disclose(applicabilityHash),
    statuteRefHash:    disclose(statuteRefHash),
    effectiveEpoch:    disclose(effectiveEpoch),
    retiredEpoch:      0 as Uint<64>,
    remittanceMode:    disclose(remittanceMode),
    registeredAt:      disclose(currentTime),
  };
  _registeredLanes.insert(dKey, disclose(record));

  // (h) Emit action kind 1 = LANE_REGISTERED.
  emitAction(
    1 as Uint<8>,
    scheduleId,
    schedRec.nodeId,
    actionHash,
    currentTime,
  );
}
```

Note on step (f): using `||` short-circuits on the `.member` check; if
the compiler rejects that shape (some Compact idioms require ternary),
Cursor MAY rewrite as:

```
if (_registeredLanes.member(dKey)) {
  assert(
    _registeredLanes.lookup(dKey).retiredEpoch != 0 as Uint<64>,
    "LANE_ALREADY_REGISTERED"
  );
}
```

Both shapes preserve the semantic (I-13.1-E) contract.

### 2.5 `retireLane` circuit

Follows V1's `retireSchedule` skeleton exactly.

**Parameter list:**

```
export circuit retireLane(
  scheduleId:   Bytes<32>,
  laneKindByte: Uint<8>,
  currentTime:  Uint<64>,
): []
```

**Action-hash payload** — vector length 6:

```
persistentHash<Vector<6, Bytes<32>>>([
  pad(32, "pp:tariff:v1:retireLane"),
  selfBytes(),
  disclose(scheduleId),
  kindBytes,                     // laneKindByte as Field as Bytes<32>
  currentEpochBytes,
  timeBytes,
])
```

**Error labels:**
- `LANE_NOT_FOUND` — key absent from `_registeredLanes`.
- `LANE_ALREADY_RETIRED` — record present but `retiredEpoch != 0`.
- `FEDERATION_APPROVAL_INVALID` — from `consumeFederationApproval`.
- `FEDERATION_APPROVAL_REPLAYED` — from `consumeFederationApproval`.

**Full-body sketch:**

```
export circuit retireLane(
  scheduleId:   Bytes<32>,
  laneKindByte: Uint<8>,
  currentTime:  Uint<64>,
): [] {
  assertInitialized();
  assert(disclose(blockTimeGte(disclose(currentTime))),
         "retireLane: timestamp cannot be in the future");

  // (a) Look up the lane.
  const key = laneKey(scheduleId, laneKindByte);
  const dKey = disclose(key);
  assert(_registeredLanes.member(dKey), "LANE_NOT_FOUND");
  const rec = _registeredLanes.lookup(dKey);

  // (b) I-13.1-F: must be active.
  assert(rec.retiredEpoch == 0 as Uint<64>, "LANE_ALREADY_RETIRED");

  // (c) Prepare hash inputs.
  const kindBytes         = (disclose(laneKindByte) as Field) as Bytes<32>;
  const currentEpochBytes = (_currentEpoch.read() as Field) as Bytes<32>;
  const timeBytes         = (disclose(currentTime) as Field) as Bytes<32>;

  const actionHash = persistentHash<Vector<6, Bytes<32>>>([
    pad(32, "pp:tariff:v1:retireLane"),
    selfBytes(),
    disclose(scheduleId),
    kindBytes,
    currentEpochBytes,
    timeBytes,
  ]);

  // (d) Federation approval + replay guard.
  consumeFederationApproval(
    actionHash,
    pad(32, "pp:tariff:v1:retireLane"),
  );

  // (e) Mark retired; re-insert.
  const retired = LaneRecord {
    scheduleId:        rec.scheduleId,
    laneKindByte:      rec.laneKindByte,
    leviedBy:          rec.leviedBy,
    bpsShare:          rec.bpsShare,
    remitAddress:      rec.remitAddress,
    basis:             rec.basis,
    applicabilityHash: rec.applicabilityHash,
    statuteRefHash:    rec.statuteRefHash,
    effectiveEpoch:    rec.effectiveEpoch,
    retiredEpoch:      _currentEpoch.read(),
    remittanceMode:    rec.remittanceMode,
    registeredAt:      rec.registeredAt,
  };
  _registeredLanes.insert(dKey, disclose(retired));

  // (f) Emit action kind 7 = LANE_RETIRED.
  //     nodeId: look it up from the parent schedule for keeper-mirror parity.
  const schedRec = _registeredSchedules.lookup(disclose(scheduleId));
  emitAction(
    7 as Uint<8>,
    scheduleId,
    schedRec.nodeId,
    actionHash,
    currentTime,
  );
}
```

Note: `retireLane` does NOT re-check charter membership. The lane was
already charter-gated at register-time; retirement is a federation-only
act that undoes a federation-only insert. This mirrors `retireSchedule`'s
shape.

### 2.6 `resolveLane` circuit

```
export circuit resolveLane(
  scheduleId:   Bytes<32>,
  laneKindByte: Uint<8>,
): LaneRecord {
  assertInitialized();
  const key = laneKey(scheduleId, laneKindByte);
  assert(_registeredLanes.member(disclose(key)), "LANE_NOT_FOUND");
  return _registeredLanes.lookup(disclose(key));
}
```

No liveness check here — caller (WI-14) checks `retiredEpoch` semantics
per its own resolution window. Same pattern as V1's `resolvePath` on
schedules (V1-DESIGN.md §4.5).

### 2.7 `resolveLanes` circuit — bounded batch

This is the WI-14 read surface. `MAX_STATUTORY_LANES = 4` per
TARIFF-SCHEDULE-MODEL §9 (reserved value; Cursor uses 4 unless
Garrett calls a bump). Fixed vector width. Fully unrolled — no
data-dependent loop, per Compact discipline (V1-DESIGN.md §5.1).

```
export circuit resolveLanes(
  scheduleId:    Bytes<32>,
  laneKindBytes: Vector<4, Uint<8>>,     // MAX_STATUTORY_LANES = 4
): Vector<4, LaneRecord> {
  assertInitialized();
  const dKinds = disclose(laneKindBytes);
  const zero = LaneRecord {
    scheduleId:        pad(32, ""),
    laneKindByte:      0 as Uint<8>,
    leviedBy:          pad(32, ""),
    bpsShare:          0 as Uint<16>,
    remitAddress:      pad(32, ""),
    basis:             0 as Uint<8>,
    applicabilityHash: pad(32, ""),
    statuteRefHash:    pad(32, ""),
    effectiveEpoch:    0 as Uint<64>,
    retiredEpoch:      0 as Uint<64>,
    remittanceMode:    0 as Uint<8>,
    registeredAt:      0 as Uint<64>,
  };
  const k0 = laneKey(scheduleId, dKinds[0]);
  const r0 = _registeredLanes.member(disclose(k0))
    ? _registeredLanes.lookup(disclose(k0)) : zero;
  const k1 = laneKey(scheduleId, dKinds[1]);
  const r1 = _registeredLanes.member(disclose(k1))
    ? _registeredLanes.lookup(disclose(k1)) : zero;
  const k2 = laneKey(scheduleId, dKinds[2]);
  const r2 = _registeredLanes.member(disclose(k2))
    ? _registeredLanes.lookup(disclose(k2)) : zero;
  const k3 = laneKey(scheduleId, dKinds[3]);
  const r3 = _registeredLanes.member(disclose(k3))
    ? _registeredLanes.lookup(disclose(k3)) : zero;
  return [r0, r1, r2, r3];
}
```

Cursor MAY prefer a helper-circuit if the ternary shape triggers
Compact idiom quirks (e.g. the `Maybe` pattern); the design admits
either implementation as long as the semantic contract holds:
zero-`LaneRecord` on missing key is the "no lane at this kind"
signal WI-14 branches on.

### 2.8 `isLaneActive` circuit

```
export circuit isLaneActive(
  scheduleId:   Bytes<32>,
  laneKindByte: Uint<8>,
): Boolean {
  assertInitialized();
  const key = laneKey(scheduleId, laneKindByte);
  if (!_registeredLanes.member(disclose(key))) {
    return false;
  }
  const rec = _registeredLanes.lookup(disclose(key));
  if (rec.retiredEpoch != 0 as Uint<64>) {
    return false;
  }
  return _currentEpoch.read() >= rec.effectiveEpoch;
}
```

Note: the final `>=` on `Uint<64>` is a numeric comparison, not on
`Field`, so it is allowed. If the compiler rejects it, rewrite as a
checked-cast helper Boolean.
