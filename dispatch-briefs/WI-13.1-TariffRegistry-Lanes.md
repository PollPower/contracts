## 0. What this brief is (and is not)

WI-13 landed the tariff-schedule surface: chartered-node schedules,
class-level split retunes, epoch versioning, federation gating. What it
did *not* land is the **per-statutory-lane record** — V1-DESIGN.md §4.3
reserved `registerLane` as a first-class federation-gated peer to
`registerSchedule` (domain tag `pp:tariff:v1:registerLane`, action kind
`1 = LANE_REGISTERED`), but the .compact file only implements the
schedule-lifecycle branch ops.

WI-14 (EBT vNext) needs those lane records to route the statutory
share to `remitAddress`es in-circuit. I-14-D requires the routing to
happen inside the settle circuit, not as a keeper trust point. Without
lane records on-chain, I-14-D is unsatisfiable as written.

**This brief is:** the spec + Cursor dispatch for adding
`LaneRecord`, `_registeredLanes`, `registerLane`, `retireLane`,
`resolveLane`, and `resolveLanes` to the WI-13 registry — as an
**additive amendment** (WI-13.1), not a fork.

**This brief is NOT:**
- A rewrite of WI-13. Every existing circuit stays bit-for-bit
  identical. The `ScheduleRecord` struct is untouched. `_classEntries`
  is untouched. Existing tests must continue to pass unchanged.
- A change to `SplitShares`. `statutoryTotalBps` stays as-is — WI-13.1
  adds the *lane-detail* map that the aggregate points to; it does
  not change the sum-to-10000 arithmetic on retunes.
- A settlement-side change. WI-14 is a separate BIG session,
  downstream.

## 2. Invariants (WI-13.1 owns these; each maps to a mechanism in the
design doc + a test in the harness)

**I-13.1-A — Federation-gated write.** `registerLane` and `retireLane`
are federation-gated via the shared `multisig_signature_valid` witness,
same skeleton as `registerSchedule` (`consumeFederationApproval` +
`_consumedFederationApprovals` replay guard + `emitAction`). No operator
key path.

**I-13.1-B — Charter binding.** `registerLane` MUST assert the target
schedule's `nodeId` is chartered via `charter_membership_proof` before
the lane record can be inserted, mirroring `registerSchedule`. A lane
cannot exist for an ungoverned schedule. (STATUTORY-LANES-MODEL §6, B-4.)

**I-13.1-C — Schedule liveness.** `registerLane` rejects if the target
schedule does not exist (`SCHEDULE_NOT_FOUND`) or is retired
(`SCHEDULE_NOT_LIVE`). Lanes attach to live schedules only.

**I-13.1-D — Epoch non-retroactivity.** A lane's `effectiveEpoch` MUST
be strictly greater than `_currentEpoch.read()` at registration.
Enforcement: bare checked-cast on
`(effectiveEpoch - currentEpoch - 1) as Uint<64>` — underflows if
`effectiveEpoch <= currentEpoch`, revert message is compiler-generic
(NO `LANE_EPOCH_RETROACTIVE` label, matching V1 convention; DRIFT-1 fix
from second-pass review). Same shape as TARIFF-SCHEDULE-MODEL C2.

**I-13.1-E — Lane uniqueness per `(scheduleId, leviedBy, laneKindByte)`.**
For a given `(scheduleId, leviedBy, laneKindByte)` triple the
registry stores at most ONE active `LaneRecord`. A second
`registerLane` on the same triple with an existing active
(non-retired) record MUST fail (`LANE_ALREADY_REGISTERED`). A retired
lane's triple may be re-registered (new record supersedes; the old
lane's `retiredEpoch` is overwritten by the new insert). Multi-authority
same-kind IS representable and expected — two different `leviedBy`
values on the same schedule at the same `laneKindByte` (e.g. KRA-VAT
and county-VAT both as `kind=0`) get distinct keys and coexist.
(HIGH-1 fix from 2026-07-16 second-pass review.)

**I-13.1-F — Retire is idempotent + audit-preserving.** `retireLane`
sets `retiredEpoch = _currentEpoch.read()`; historical `resolveLane`
at prior epochs still returns the record. Retiring an already-retired
lane fails (`LANE_ALREADY_RETIRED`). Retired records remain in
`_registeredLanes` at their original key with `retiredEpoch != 0`,
until explicitly overwritten by re-registration at the same
`(scheduleId, leviedBy, laneKindByte)` triple. For durable audit trail
across re-registration events, the off-chain indexer MUST snapshot the
`LaneRecord` state on each `LANE_REGISTERED` and `LANE_RETIRED` event.
On-chain versioned history is deferred to WI-13.2 if required.

**I-13.1-G — Read-only views never mutate.** `resolveLane`,
`resolveLanes`, `isLaneActive` write nothing to ledger and emit no
events. `resolveLanes` iterates a bounded fixed-width vector (see
I-13.1-H).

**I-13.1-H — Bounded lane enumeration.** `resolveLanes` accepts two
parallel vectors `leviedBys: Vector<MAX_STATUTORY_LANES, Bytes<32>>`
and `laneKindBytes: Vector<MAX_STATUTORY_LANES, Uint<8>>` (fixed width
per Compact discipline) and returns
`Vector<MAX_STATUTORY_LANES, LaneRecord>`. `leviedBys[i]` and
`laneKindBytes[i]` pair up to identify the i-th lane request.
Unpopulated request slots return the zero `LaneRecord`. This is
WI-14's read surface: v8's settle circuit reads the lane set for the
relevant class + epoch (keeper-mirrored from `_registeredLanes` map
state), then routes each populated `remitAddress` in-circuit.
`MAX_STATUTORY_LANES` is fixed at compile time at **10** (upgraded
from 4 in the pre-review draft per 2026-07-16 review call, sized for
multi-authority statutory environments like Kenya's KRA + EPRA +
county + WARMA + PDL + RDL stack).

**I-13.1-I — Per-schedule lane count cap.** The count of live and
retired lanes at distinct `(leviedBy, laneKindByte)` keys per schedule
MUST NOT exceed `MAX_STATUTORY_LANES` (= 10). Enforcement:
`_registeredLaneCount` ledger map, incremented on fresh registration
(when the composite key is not already present in `_registeredLanes`),
never decremented. Re-registration at an existing retired key does
NOT increment. Overflow: bare checked-cast revert on
`(MAX_STATUTORY_LANES - priorCount - 1) as Uint<8>`.

**I-13.1-J — laneKindByte range.** `laneKindByte` MUST be in range
`[0, 16)`. Enforcement: bare checked-cast on
`(16 - laneKindByte - 1) as Uint<8>` in `registerLane`. Overflow:
bare checked-cast revert. The 0..15 range is reserved for
statute-defined lane kinds; higher values are disallowed to keep
the space bounded for future off-chain interpretation.

## 3. Circuit signatures (Cursor implements against these; may
refine names/param order in the design doc, but semantic surface is
fixed)

### 3.1 New struct

```
struct LaneRecord {
  scheduleId:        Bytes<32>,
  laneKindByte:      Uint<8>,        // 0=VAT, 1=levy, 2=cess, 3=duty (STATUTORY-LANES-MODEL §2)
  leviedBy:          Bytes<32>,      // authority id ("KRA", "EPRA", county-id, ...)
  bpsShare:          Uint<16>,       // statute-set; consistent with parent schedule's statutoryTotalBps
  remitAddress:      Bytes<32>,      // authority address OR licensed remittance escrow
  basis:             Uint<8>,        // 0=pre-tax energy charge, 1=full retail price, ...
  applicabilityHash: Bytes<32>,      // commitment to the per-class applicability rule
  statuteRefHash:    Bytes<32>,      // hash of enabling-law citation
  effectiveEpoch:    Uint<64>,
  retiredEpoch:      Uint<64>,       // 0 = live; nonzero = retired at that epoch
  remittanceMode:    Uint<8>,        // CAL-11: 0=fiat-door, 1=on-chain (STATUTORY-LANES-MODEL §3)
  registeredAt:      Uint<64>,       // block time
}
```

### 3.2 New ledger fields

```
export ledger _registeredLanes: Map<Bytes<32>, LaneRecord>;
export ledger _registeredLaneCount: Map<Bytes<32>, Uint<8>>;
```

`_registeredLaneCount` enforces I-13.1-I; keyed by `scheduleId`,
incremented on fresh registration (composite key not yet present in
`_registeredLanes`), never decremented on retire. Bounded by
`MAX_STATUTORY_LANES = 10`.

Key derivation (composite, 3-tuple after HIGH-1 fix):
```
circuit laneKey(
  scheduleId:   Bytes<32>,
  leviedBy:     Bytes<32>,
  laneKindByte: Uint<8>,
): Bytes<32> {
  const kindBytes = (disclose(laneKindByte) as Field) as Bytes<32>;
  return persistentHash<Vector<4, Bytes<32>>>([
    pad(32, "pp:tariff:v1:laneKey"),
    disclose(scheduleId),
    disclose(leviedBy),
    kindBytes,
  ]);
}
```

### 3.3 Circuits

**`registerLane`** — federation-gated branch op:
```
export circuit registerLane(
  scheduleId:        Bytes<32>,
  laneKindByte:      Uint<8>,
  leviedBy:          Bytes<32>,
  bpsShare:          Uint<16>,
  remitAddress:      Bytes<32>,
  basis:             Uint<8>,
  applicabilityHash: Bytes<32>,
  statuteRefHash:    Bytes<32>,
  effectiveEpoch:    Uint<64>,
  remittanceMode:    Uint<8>,
  charterProof:      CharterProof,   // schedule's nodeId is chartered
  currentTime:       Uint<64>,
): []
```
Skeleton: `assertInitialized` → `blockTimeGte(currentTime)` → schedule
exists + live → charter check on `rec.nodeId` → I-13.1-D check
(`effectiveEpoch > currentEpoch`, bare checked-cast) → I-13.1-J check
(`laneKindByte < 16`, bare checked-cast) → I-13.1-I check
(`priorCount < MAX_STATUTORY_LANES`, bare checked-cast) → build
action-hash over `[domain "pp:tariff:v1:registerLane", selfBytes,
scheduleId, laneKindBytes, leviedBy, bpsShareBytes, remitAddress,
basis, applicabilityHash, statuteRefHash, effectiveEpochBytes,
remittanceModeBytes, currentEpochBytes, timeBytes]` →
`consumeFederationApproval(actionHash, domain)` → I-13.1-E check
(no active lane at composite key) → build `LaneRecord` with
`retiredEpoch = 0` →
`_registeredLanes.insert(laneKey(scheduleId, leviedBy, laneKindByte),
record)` → if key was fresh, `_registeredLaneCount.insert(scheduleId,
priorCount + 1)` → `emitAction(kind=1 LANE_REGISTERED, scheduleId,
rec.nodeId, actionHash, currentTime)`.

**`retireLane`** — federation-gated branch op:
```
export circuit retireLane(
  scheduleId:   Bytes<32>,
  leviedBy:     Bytes<32>,
  laneKindByte: Uint<8>,
  currentTime:  Uint<64>,
): []
```
Reserve new action-kind byte `7 = LANE_RETIRED` (V1-DESIGN.md §3.1
extends). Skeleton mirrors `retireSchedule`: lookup by
`laneKey(scheduleId, leviedBy, laneKindByte)`, assert active
(`retiredEpoch == 0`), rebuild 7-element action-hash (adds `leviedBy`
at position 4), consume federation approval, set
`retiredEpoch = _currentEpoch.read()`, re-insert record, emit action
kind=7. `_registeredLaneCount` is NOT decremented (slot preserved for
audit continuity per I-13.1-I). If the RegistryActionEntry kind range
needs a new enum constant beyond current 0..6, document in the design
doc.

**`resolveLane`** — read-only view:
```
export circuit resolveLane(
  scheduleId:   Bytes<32>,
  leviedBy:     Bytes<32>,
  laneKindByte: Uint<8>,
): LaneRecord
```
Compute `laneKey(scheduleId, leviedBy, laneKindByte)`, assert
`_registeredLanes.member(key)` (`LANE_NOT_FOUND`), return the record.
No liveness check here — caller (WI-14) checks `retiredEpoch`
semantics per its own resolution window (same pattern as
`resolvePath` on schedules).

**`resolveLanes`** — bounded batch view (Option A parallel-vector
signature per second-pass review):
```
export circuit resolveLanes(
  scheduleId:    Bytes<32>,
  leviedBys:     Vector<MAX_STATUTORY_LANES, Bytes<32>>,
  laneKindBytes: Vector<MAX_STATUTORY_LANES, Uint<8>>,
): Vector<MAX_STATUTORY_LANES, LaneRecord>
```
`leviedBys[i]` and `laneKindBytes[i]` pair up to identify the i-th
lane request. Iterate the fixed-width vectors. For each slot, compute
`laneKey(scheduleId, leviedBys[i], laneKindBytes[i])` — if
`_registeredLanes.member` returns true, populate the return slot from
lookup; otherwise return a zero `LaneRecord`. WI-14 uses this to
fetch all lanes for a schedule in one read; unpopulated slots are
the natural "no lane at this key" signal. Deduplication of
`(leviedBy, laneKindByte)` pairs across slots is WI-14's keeper-side
responsibility (see design §7.2). No `resolveLanesActive` variant is
defined; the "populated + live" predicate is WI-14's job per design
§7.

**`isLaneActive`** — read-only Boolean:
```
export circuit isLaneActive(
  scheduleId:   Bytes<32>,
  leviedBy:     Bytes<32>,
  laneKindByte: Uint<8>,
): Boolean
```
Mirrors `isScheduleActive`. Returns false if not found, or if
`retiredEpoch != 0`, else true.

## 4. Compile + test discipline

- Compile on Kenya via absolute compactc path. Full ZK, no
  `--skip-zk`. All existing WI-13 tests (T1..T7, T3.5, F-4, F-7a/b,
  R-A/R-B/R-C) MUST still pass unchanged. Regression protection is the
  strongest safety net for this being additive.
- New tests, at minimum (post-second-pass count = 14):
  - **LANE-T1 (happy path):** registerLane on a live chartered
    schedule, effectiveEpoch = current+1, resolves back byte-for-byte.
  - **LANE-T2 (charter fail):** registerLane on a schedule whose
    nodeId is not in `_governanceRoot` fails with
    `SCHEDULE_UNCHARTERED_NODE`.
  - **LANE-T3 (schedule retired):** registerLane against a retired
    schedule fails `SCHEDULE_NOT_LIVE`.
  - **LANE-T4 (retroactive):** effectiveEpoch <= currentEpoch reverts
    via bare checked-cast underflow (compiler-generic message; NO
    `LANE_EPOCH_RETROACTIVE` label, matching V1 convention).
  - **LANE-T5 (FLIPPED SEMANTIC — multi-authority same-kind succeeds):**
    register `(schedA, KRA, kind=1)` then register
    `(schedA, county, kind=1)` — both succeed at distinct composite
    keys. This is the HIGH-1 fix invariant: multi-authority same-kind
    IS representable.
  - **LANE-T5b (NEW — exact-key duplicate fails):** register
    `(schedA, EPRA, kind=1)`, register the same triple again →
    `LANE_ALREADY_REGISTERED`. True uniqueness test at the composite
    key.
  - **LANE-T6 (retire happy):** retireLane sets retiredEpoch,
    subsequent isLaneActive returns false, resolveLane still returns
    the record.
  - **LANE-T7 (retire idempotent):** retireLane on already-retired
    fails `LANE_ALREADY_RETIRED`.
  - **LANE-T8 (federation replay):** replaying a captured
    registerLane action-hash fails `FEDERATION_APPROVAL_REPLAYED`.
  - **LANE-T9 (resolveLanes batch — EXTENDED):** cover heterogeneous
    cases in one call:
    - (a) populated slot,
    - (b) empty-slot (zero-address / zero-kind pair not in map),
    - (c) retired-lane-in-slot (returns record with `retiredEpoch != 0`),
    - (d) not-yet-effective lane (returns record with
      `effectiveEpoch > currentEpoch`),
    - (e) duplicate `(leviedBys[i], laneKindBytes[i])` pair supplied
      twice returns the same record in both slots (dedup is WI-14
      keeper's responsibility per design §7.2).
  - **LANE-T10 (NEW — count-cap enforcement):** register 10 lanes on
    one schedule at 10 distinct `(leviedBy, laneKindByte)` keys, then
    try to register an 11th → bare checked-cast revert. Verify
    `_registeredLaneCount.lookup(scheduleId) == 10` after the 10
    successful registrations.
  - **LANE-T11 (NEW — resolveLanes width-10 round trip):** register 10
    lanes on one schedule, call `resolveLanes(scheduleId, leviedBys,
    laneKindBytes)` with all 10 pairs, verify all 10 return records
    have matching non-zero `scheduleId` and correct
    `(leviedBy, laneKindByte)` per slot.
  - **LANE-T12 (NEW — kind-range enforcement):** register with
    `laneKindByte = 16` → bare checked-cast revert. Also verify
    `laneKindByte = 15` succeeds (upper boundary inclusive of 15,
    exclusive of 16).
  - **LANE-R-A (charter forge post-rotation):** a valid charter
    proof for `_governanceRoot`v1 fails to register a lane after
    `advanceEpoch` rotates to `_governanceRoot`v2.
  - **LANE-R-E (uniqueness after re-registration):** register →
    retire → register-again on the same
    `(scheduleId, leviedBy, laneKindByte)` triple succeeds; the new
    record supersedes and `_registeredLaneCount` does NOT increment
    on the re-registration (slot was already claimed at first
    registration).

New test count: 14 (T1..T12 with T5 flipped + T5b + T10 + T11 + T12
+ R-A + R-E). All 15 existing WI-13 regression tests must still pass
unchanged.

- Test harness lives under `tariff-registry/tests/`. Extend the
  existing `lib.mjs` mirror with `laneKey(scheduleId, leviedBy,
  laneKindByte)` (4-element vector hash), `registerLane` action-hash
  reconstruction (14-element vector), `retireLane` action-hash
  reconstruction (7-element vector — was 6 pre-review; adds
  `leviedBy` at position 4), and a zero-record helper. The mirror
  MUST NOT emit any `LANE_EPOCH_RETROACTIVE` error string — bare
  checked-cast reverts surface as compiler-generic underflow. Same
  `node:test` + `node:crypto` discipline as WI-13. No new deps.
